# Recall Lens：審査基準に基づく追加検証

更新：2026-10-26。追加実験を完了。詳しい結果は `DIVERSE_PHOTO_STUDY.md` と技術レポートに収録した。

新しい144枚・96ペア・24空間ブロックを固定し、4方式・34設定・両方向で計6,528件を計算した。画像とファイルハッシュの調整／評価間重複はない。AIによる2回の画像確認で一致した74ペアを採用し、曖昧・不一致の22ペアを除外した。人が確認した正解ではない。調整側35ペアだけで設定を選び、ラベルと設定を固定後、評価側39ペアを一度評価した。

評価側では現行ORBが一致12/28方向、誤受理0/50方向、調整SIFTが一致19/28方向、誤受理3/50方向。調整ORBは15/28方向・0/50方向だが、選ばれた閾値が低く、幾何検証前の少数対応点でも受理する問題がある。現行アプリの設定は変更していない。単一利用者の写真、AIラベル、連写に近い写真、曖昧例の除外という制約を併記した。

調整処理の自動確認では、最終評価側で良い設定が調整時の選択へ混入しないこと、未確認のモデル提案を採用しないことを検証した。既存の人手ラベル49ペアと端末・AWSの6試行は、今回の探索的評価と分けて残した。方式比較・調整曲線・処理時間の3図、実写2ペアの成功／失敗図を追加した。

## 何を改善するための実験か

[公式Rules](https://opencv26.devpost.com/rules)は、技術・実装・信頼性・評価を30%、独創性20%、実用上の価値20%、UX10%、資料10%、クラウド・再現性・責任ある運用10%としている。アルゴリズムの比較本数やグラフ数そのものに配点はない。比較により設計判断と適用範囲を説明し、失敗が利用体験にどう影響するかを示す。

| 基準 | 現在の不足 | 追加する証拠 |
|---|---|---|
| 技術・評価 30% | 正例が8枚・1候補群に集中。比較方式の閾値が別途調整されていない | 新しい24空間ブロックの実写、調整／評価の分離、複数方式とパラメーターの比較 |
| 実用上の価値 20% | 使える場面・使えない場面の説明が抽象的 | 画像の種類別の成功・誤受理・見逃し、実写事例、利用可能な条件の明示 |
| 独創性 20% | 既存方式を使う理由と体験との関係が弱い | 同じ場所でも異なる対象を区別する必要性、色・意味の類似と幾何的一致の違い |
| UX 10% | なぜ開かないのかを利用者が判断しにくい | 実験から裏付けられる撮影時の案内・適用対象の説明。導入は効果を確認した小変更に限る |
| 資料 10% | 少数例の成績が中心 | 方式比較表、閾値と誤受理・見逃しの曲線、失敗例、判断理由 |
| クラウド等 10% | 画像評価と通信評価が混ざりやすい | 画像照合の精度／端末性能／AWS通信を別評価として追跡する |

この対応は評価改善を狙う方針であり、得点上昇や入賞を保証するものではない。

## 追加データの設計

- 以前の641枚と既存49ペアの画像を除外して選ぶ。
- 有効GPSとローカルにある原本から候補を作る。画像スコアによる事前選別を使わない。
- 中心が500m以上離れた24空間ブロックから各6枚を時間順に分散して選び、4ペアずつ作る。計144枚・96ペア。
- ブロック単位で12ブロックを調整用、12ブロックを最終評価用に固定する。写真をまたがせない。
- GPSは候補抽出用であり、同じ視覚対象の正解ラベルではない。近接・別日という理由だけで同一と判定しない。
- 端末にある写真・有効GPSに限定される偏りは残る。空間ブロックの数を利用者数や独立した意味的シーン数とは呼ばない。

## 方式と調整項目

1. HSV色分布：軽量な大域的外観の比較。
2. ORB対応点数：幾何検証を省いた比較。
3. ORB + RANSAC：現行方式。
4. SIFT + RANSAC：別の特徴抽出方式との比較。

ORBの特徴点数800／1,600、対応点の比率条件0.65／0.75／0.85、RANSAC許容幅2／4／8ピクセルを調べる。SIFTは1,600特徴点を上限目標とし、同じ比率条件・許容幅を比較する。現行設定は別に固定して残す。比較設定は合計34通り。

方式ごとの閾値と設定は調整用ラベルだけで選ぶ。事前に定めた選択基準は「調整用で観測された誤受理率5%以下の範囲で正例の受理を最大化し、同率なら誤受理の少なさ、比較時間、設定IDで決める」。5%は選択基準であり、真の誤受理率の保証ではない。

最終評価用の結果は、選択結果を保存してから開く。成績を見て最終評価用の画像や閾値を入れ替えない。失敗した設定も残す。特徴抽出時間と照合時間を分け、端末・AWSの速度とは混同しない。

## ビジョンモデルの役割

画像の分類、視野の重なり、照明・角度・遮蔽・低テクスチャ等の特徴、失敗原因の仮説を整理する。アルゴリズムの点数や判定は、視覚ラベル作成の際には見せない。

モデルの提案は暫定ラベル。曖昧なペアは不明として残し、正解として強制採用しない。独立確認の範囲・修正件数を記録し、モデルが作った正解と人が確認した正解を区別する。画像を見ただけの原因推定と、条件を変えた実験による原因検証も区別する。

既存のlocal-llm-workerはChatGPTへの添付送信を行う実装であり、ユーザーの許可を得て実施した。OpenCVの数値計算は端末内で実行した。

## 提出に反映する条件

- 正解ラベルとデータ分割が成立しない場合は、閾値調整を「精度改善の実証」と呼ばない。
- 最終評価で改善が確認できても、実装・処理時間・端末での検証が済むまではアプリ採用済みと書かない。
- [公式提出要件](https://opencv26.devpost.com/)の動作デモ動画・審査員アクセス・提出手続きに必要な時間を確保する。比較本数を無制限に増やさない。
